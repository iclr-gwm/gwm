Key contributions

Inspectable memory. Frozen policy.

01

Latent workflow discovery

Interaction prefixes are embedded and clustered into workflow states, then linked to observed successors, outcome rates, support counts, and examples.

02

Frozen-policy guidance

The harness injects sparse advice or ranks best-of-K candidates using graph evidence while keeping the acting model unchanged.

03

Reuse analysis

Experiments separate in-domain reuse, cross-benchmark transfer, cross-model guidance, candidate availability, and selection error.

Broader impact

Ground the next action in workflow evidence

GWM is designed for accountable deployment settings where teams need to inspect what past workflows support a recommendation, preserve policy weights, and keep independent enterprise rules in force.

Transparent memory Graph nodes expose support, outcomes, transitions, and examples.
Portable serving Graph adapters load beside local vLLM or a compatible remote API backend.
Privacy boundary Released materials should keep trajectories sanitized and permissioned.

Paper explorer

Workflow memory, without retraining.

GWM discovers recurring workflow states from interaction histories and turns them into inspectable memory. The same frozen graph can advise an agent or rank its candidate continuations while the policy’s weights stay fixed.

Transfer

Workflow memory transfers across benchmarks.

All eight evaluated cross-benchmark configurations exceed their target single-generation baseline. In-domain graphs lead in three of the four available matched comparisons.

Table 7 · Historical Qwen evaluation. Shared detail scale: 35–55% task success. Discovery fractions are task subsets. Target policy, tasks, evaluator, and selector settings are held fixed. Uncertainty is not included in this website summary.

Q1

Experience can cross model boundaries

Qwen-derived CRM memory supports Gemma. In the evaluated comparison, GWM-L reaches 52.33% success versus 47.33% for GWM-S.

Q2

Workflow states carry outcome evidence

Node statistics reach 0.745 AUROC, with a 95% task-cluster bootstrap CI of [0.725, 0.765], across 65,994 observed prefixes from 1,479 held-out tasks.

Q3

The benefit has practical limits

More graph states do not guarantee better guidance. Replay analysis separates missing useful candidates from selection errors; historical regularities still require live context.

vLLM extension

Bring workflow memory to vLLM.

Load named graph adapters alongside the model server. Per-request options choose advice or candidate selection through the endpoint plugin interface, with zero changes to vLLM core.

    Use GWM with your agent

    Install once. Build and serve.

    Turn labelled, multi-turn conversations with tool calls into a graph adapter. A compatible agent sends its history to the endpoint and receives one selected continuation.

    From the cloned repository, use a Python 3.11+ environment supported by vLLM. Supply your conversation corpus as rollouts.jsonl and replace MODEL_ID with your serving model.

    $_ Install One command
    python -m pip install -e ".[server,model,build]" vllm

    GWM, graph-building dependencies, and vLLM.

    $_ Build + serve One command
    vllm-gwm build --input rollouts.jsonl --adapter agent --output graphs/agent && \
VLLM_PLUGINS=gwm vllm-gwm serve --gwm-modules agent=graphs/agent MODEL_ID

    Build from your labelled rollouts, then start the inference endpoint.

    $_ Continue a conversation K = 2
    curl -sS http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' --data-binary @request.json

    Download request.json ↗ · Set its model and matching preset, then send it to the running server.

    Request xargs JSON
    {
  "vllm_xargs": {
    "gwm.adapter": "agent",
    "gwm.preset": "YOUR_PRESET",
    "gwm.mode": "select",
    "gwm.k": 2,
    "gwm.episode_id": "report-example"
  }
}

    Include these fields in the request body. Choose your adapter and matching preset; gwm.k sets the number of candidates.

    History + tool results → vLLM + GWM → one next response. Your agent executes any returned tool action, appends its result, and repeats.

    Conversation formats and setup

    The request example includes a prior assistant tool call, its tool result, and a follow-up user turn. It asks for a text continuation using that history. Replace MODEL_ID and YOUR_PRESET with your model and an installed preset matching your agent’s tools and action format. Use your model’s usual chat template and tool-parser options when serving native tool calls.

    Multi-turn request
    {
  "model": "MODEL_ID",
  "messages": [
    {
      "role": "system",
      "content": "Use the recorded tool results to answer the user."
    },
    {
      "role": "user",
      "content": "Check whether the reviewer has access to the report."
    },
    {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_access",
          "type": "function",
          "function": {
            "name": "get_report_access",
            "arguments": "{\"report_id\": \"report-example\"}"
          }
        }
      ]
    },
    {
      "role": "tool",
      "tool_call_id": "call_access",
      "name": "get_report_access",
      "content": "{\"reviewer_access\": \"granted\"}"
    },
    {
      "role": "user",
      "content": "Summarize the current access in one sentence."
    }
  ],
  "vllm_xargs": {
    "gwm.adapter": "agent",
    "gwm.preset": "YOUR_PRESET",
    "gwm.mode": "select",
    "gwm.k": 2,
    "gwm.episode_id": "report-example"
  }
}

    For building, use JSONL records with conversation_flow events and explicit overall_success labels, or the plugin’s collected-rollout format. Download a rollout format example. This single record demonstrates the schema; build from a corpus of successful and failed conversations.

    Conversation histories and outcome labels must be normalized into this format. For preset configuration and agent integration, see the implementation guide and runnable examples.

    Advise K = 1. Inject sparse graph-grounded guidance only when a trap or retry loop triggers.
    Select K greater than 1. Generate candidates once, score them jointly, return one winner.
    Evolve · future work Collection and rebuild tools support future graph updates. These capabilities are outside the paper’s evaluated contributions.
    Inspect Use `/v1/gwm/*` and the opt-in `/v1/graph` viewer for adapter state and graph checks.
